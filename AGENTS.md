## 1. Что это за проект

Личный сайт автора — «учительский магазин»: игры и тренажёры для уроков информатики (учебник Босовой, ОГЭ),
позже курсы и программы. Главная — стена с короткими роликами геймплея, как в ВК; группа ВК — витрина.
Сейчас всё бесплатно, но сайт строится так, чтобы позже включить подписку на отдельные продукты и режимы.

Пока проект — **только статический сайт**. Не добавляй сервер, базу данных, авторизацию,
платежи или сторонние сервисы без прямой просьбы автора (см. раздел 9).

**Адреса не ломаем.** Наружу (посты, QR, печать) уходят только адреса страниц (`/item/<slug>/`,
`/igra/<slug>/`), не прямые ссылки на файлы игр. Slug после публикации не меняется. Подробно — `docs/SITE.md`.

## 2. Стек и команды

- [Astro](https://astro.build) 7, TypeScript, без UI-фреймворков (React/Vue не подключать).
- Контент — Markdown-файлы с frontmatter в коллекции `items`.
- QR-коды генерируются при сборке пакетом `qrcode`.
- Публикация — GitHub Pages через `.github/workflows/deploy.yml`.

```bash
npm install
npm run dev       # http://localhost:4321/personal_ebsite/
npm run build     # обязательно перед завершением задачи — сборка должна пройти без ошибок
npm run preview
```

Адрес сайта задаётся в `astro.config.mjs` (`site`, `base`). Сейчас `base: '/personal_ebsite'`.
**Все внутренние ссылки строй через `import.meta.env.BASE_URL`** или функции из `src/lib.ts`
(`openHref`, `pageHref`). Ссылки вида `href="/catalog"` сломаются на GitHub Pages.

## 3. Структура

```

  content/items/*.md     карточки материалов, одна на файл; имя файла = адрес страницы
  lib.ts                 openHref, pageHref, gradeLabel
  layouts/Base.astro     шапка, подвал, мета-теги
  components/Card.astro  карточка в списках
  pages/index.astro      главная: разделы по классам, курсы, программы
  pages/catalog.astro    каталог с фильтрами (type, grade, q — сохраняются в адресе)
  pages/item/[id].astro  страница материала с QR-кодом
  styles/global.css      токены цвета и шрифтов, светлая и тёмная тема
public/
  games/*.html           сами игры — самодостаточные HTML-файлы
  favicon.svg

docs/                    планы и описания миров больших игр (docs/klever/ — «Клевер»)
tests/                   автотесты (node:test)
```

## 4. Как добавить материал (самая частая задача)

1. Игру положи в `public/games/<slug>.html`. Slug — латиница через дефис, транслит названия
   (`zvezdnaya-pochta`, `istinno-lozhno`).
2. Создай `src/content/items/<slug>.md`:

```markdown
---
title: Звёздная почта
type: trainer                 # game | trainer | course | app
summary: "Одно-два предложения для карточки"
emoji: 📡
color: "#3B2F9E"              # основной цвет игры, им красится обложка карточки
url: games/zvezdnaya-pochta.html   # без ведущего слеша; внешние — полным адресом https://…
access: free                  # free | paid | external | soon
grades: [7]
topic: "Измерение информации (алфавитный подход)"
textbook: "Босова, 7 класс — измерение информации"
duration: "10 минут"
format: [за компьютерами, на доске]
modes: [тренировка, контрольная на 10 минут с оценкой]
tags: [бит, байт, ОГЭ]
order: 20                     # порядок в списках: 7 класс — 10–29, 8 класс — 30–99, курсы — 200+, программы — 300+
added: 2026-10-12             # дата публикации; самый свежий материал показывается в блоке «Новое» на главной
---
Описание и раздел «Как использовать на уроке» — обычный Markdown.
```

3. Строковые значения с двоеточием, кавычками или тире в начале **бери в кавычки** — иначе YAML не разберётся.
4. Запусти `npm run build` и убедись, что появилась страница `/item/<slug>/`.

Нужно новое поле? Сначала добавь его в `src/content.config.ts` (с `.optional()` или `.default()`,
чтобы старые карточки не сломались), потом выводи в шаблонах.

## 5. Правила для самих игр (`public/games/*.html`)

Все игры сделаны по одному образцу — сохраняй его в новых и изменённых играх.

**Файл**
- Один самодостаточный HTML: CSS и JS внутри файла. Никаких сборщиков, npm-пакетов и модулей.
- Внешние ресурсы — только шрифты Google Fonts с запасными шрифтами в `font-family`.
- Картинки — inline SVG или data-URI. Никаких запросов к другим сайтам: игра должна работать
  в школьной сети с фильтрами и открытой с флешки.
- `localStorage` только для удобств (рекорд, звук) и **всегда в `try/catch`** — без него игра обязана работать.

**Интерфейс**
- Весь текст — по-русски, обращение к ученику на «ты».
- Читаемость на проекторе: крупные цифры и кнопки, высокий контраст.
- Цвета — переменными в `:root`, тёмная тема через `prefers-color-scheme`.
- `<meta name="viewport" ... viewport-fit=cover>` и отступы `env(safe-area-inset-*)`.
- Управление и мышью/касанием (интерактивная доска), и с клавиатуры. Esc — пауза.
- `prefers-reduced-motion` — отключать лишнюю анимацию.

**Обязательные части каркаса**
- Стартовый экран с вкладками «📝 Контрольная на оценку» и «🎯 Тренировка».
- Контрольная: поле «Фамилия и имя» (без него не начать), таблица баллов и оценок, правила,
  ровно 10 минут по настоящим часам (`Date.now()`, без паузы), подсчёт уходов со страницы
  (`visibilitychange`), экран результата с оценкой, датой и разбивкой по типам заданий.
- Все параметры контрольной — в объекте `EXAM` в начале скрипта (время, порядок заданий,
  баллы, штраф за ошибку, пороги оценок), чтобы учитель мог поменять их за минуту.
- Тренировка: настройки, очки, серия и множитель, рекорд.
- Каждая ошибка **объясняется**: не «неверно», а почему и как правильно, с вычислением.
- Экран итогов с блоком «Над чем поработать» по типам ошибок.
- Справка с теорией по теме (в контрольной отключена).

**Методика**
- Опирайся на учебник Босовой и формат ОГЭ. Термины и обозначения — как в учебнике.
- Не вводи ошибочных упрощений (пример того, чего нельзя: «.exe — это вирус»).
- Задания по возможности генерируются, а не берутся из фиксированного списка, и отсекают
  вырожденные случаи (одинаковые варианты, константы, ответ виден без вычислений).
- Варианты-ловушки строй на типичных ошибках учеников, а не случайно.

**Проверка игры** — перед сдачей прогони автотест в Node + `jsdom`: загрузи файл,
программно реши по 20–40 заданий каждого типа и уровня через функции игры, проверь,
что каждое доходит до состояния «решено», и пройди сценарий контрольной с переводом
времени (`S.t0 -= 11 * 60 * 1000`) — должен появиться экран с оценкой. Тестовые скрипты
не коммить в `public/`.

После добавления или изменения игры обнови её карточку в `src/content/items/`.

**Большие игры.** Если игра больше ~1500 строк (например, «Клевер»), она пишется модулями
в `games-src/<игра>/`, тестируется через `node --test` и собирается в один файл
`public/games/<игра>.html` скриптом `scripts/build-game.mjs`. Готовый файл подчиняется всем
правилам выше. План и мир такой игры лежат в `docs/<игра>/` — читай их перед работой.

**Чужие миры и персонажи.** Не используем узнаваемых персонажей, названия, термины и образы
из книг, фильмов, мультфильмов и игр (даже «в честь»). Вдохновение жанром — можно,
заимствования — нельзя.

## 6. Стиль кода

- TypeScript в `.astro` и `.ts`; в играх — современный JS без библиотек.
- Имена переменных и функций — по-английски, комментарии — по-русски и только там, где неочевидно.
- Не переформатируй файлы целиком и не переименовывай без нужды — дифф должен показывать суть правки.
- Стили компонентов — в `<style>` внутри компонента; общие токены — только в `global.css`.
- Не добавляй зависимости без необходимости. Новая зависимость — объясни в ответе зачем.

## 7. Тексты на сайте

- Пишем для учителя информатики: коротко, по делу, без маркетинговых штампов.
- В описании материала всегда есть «Как использовать на уроке».
- Не выдумывай факты об авторе, курсах, номерах параграфов и ценах — если не знаешь, оставь поле пустым
  и скажи об этом в ответе.

## 8. Перед тем как сказать «готово»

- [ ] `npm run build` проходит без ошибок и предупреждений о контенте
- [ ] новые страницы открываются через `npm run preview` с учётом `base`
- [ ] нет абсолютных внутренних ссылок без `BASE_URL`
- [ ] для игр — автотест пройден, карточка обновлена
- [ ] в ответе перечислено, какие файлы изменены и что проверить руками

## 9. Решения, которые принимает только автор

Спроси, прежде чем делать:
- серверная часть, база данных, авторизация, личные кабинеты;
- платежи (ЮKassa, Robokassa и т. п.) и всё, что связано с деньгами и чеками;
- хранение персональных данных учеников и пользователей — по 152-ФЗ данные граждан РФ
  должны храниться на серверах в России, поэтому выбор хостинга и сервисов согласуется заранее;
- аналитика, счётчики, сторонние скрипты;
- смена стека, хостинга или домена;
- удаление материалов и изменение адресов страниц (на них могут вести QR-коды и посты ВК).
