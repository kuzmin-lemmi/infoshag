# План разработки игры «Клевер» — для работы в Claude Code

Перед началом любого этапа прочитай: `AGENTS.md` (правила проекта), `docs/klever/WORLD.md` (мир игры),
этот файл. Работай **строго по одному этапу за сессию**. Не забегай вперёд и не делай то,
что запланировано на следующие этапы.

## 1. Что делаем

Исполнитель Робот в стиле КуМира с сюжетной кампанией. Марсоход Клевер возрождает сады
на пустынном Марсе; ученик управляет им программой.

- Аудитория: 8 класс, «Основы алгоритмизации» (Босова) + подготовка к заданию ОГЭ с Роботом.
- Главная учебная цель: писать **общий** алгоритм, который работает на любом поле нужного вида.
- Ключевая механика: каждый уровень проверяется сразу на нескольких **вариантах поля**,
  поэтому подогнанное под одну картинку решение не проходит.

## 2. Архитектура

Игра большая, поэтому, в отличие от остальных игр, она пишется **модулями** и собирается
в один HTML-файл. Итоговый файл подчиняется всем правилам из AGENTS.md (самодостаточный,
без запросов к другим сайтам, кроме шрифтов).

```
games-src/klever/
  template.html        разметка экранов и стили; сюда вставляется собранный скрипт
  main.js              точка входа: связывает модули, экраны, обработчики
  world.js             поле: разбор ASCII-карты, стены, объекты, копирование состояния
  program.js           дерево программы: создание, вставка, удаление, подсчёт блоков
  interpreter.js       выполнение дерева по шагам (генератор), лимит шагов, аварии
  checker.js           проверка решения на всех вариантах, звёзды
  kumir.js             дерево → текст КуМира; на этапе 4 — текст → дерево с ошибками
  levels.js            кампания: главы и уровни
  editor.js            блочный редактор программы
  render.js            отрисовка поля и Клевера в SVG, анимации
  exam.js              контрольная на 10 минут
  storage.js           прогресс в localStorage (всегда в try/catch)
  level-link.js        упаковка уровня в ссылку и обратно (этап 6)
scripts/build-game.mjs сборка: esbuild бандлит main.js → вставляется в template.html
                       → public/games/klever.html
tests/klever/*.test.mjs автотесты на встроенном node:test
```

Правило зависимостей: `world`, `program`, `interpreter`, `checker`, `kumir`, `levels`
**не знают о DOM** и тестируются в Node. Всё, что рисует и слушает клики, — только в
`editor`, `render`, `main`, `exam`.

Новые dev-зависимости: только `esbuild`. В `package.json` добавить скрипты:

```json
"game:klever": "node scripts/build-game.mjs klever",
"test": "node --test tests/"
```

## 3. Форматы данных

### Карта поля (ASCII)

Клетки стоят на нечётных позициях, между ними — стены. Так стены могут быть между
клетками, как в КуМире.

```
+---+---+---+---+
| S   .   * | F |
+   +---+   +   +
| .   #   ~   . |
+---+---+---+---+
```

Обозначения в клетке: `S` старт, `F` финиш (росоуловитель), `*` грядка (цель),
`#` камень, `d` сухая грядка, `w` грядка с сорняком, `~` солончак, `q` зыбучий песок,
`.` или пробел — пустой песок. Вертикальная стена — `|`, горизонтальная — `---`.
Внешняя рамка обязательна. Разбор и обратная печать — в `world.js`.

### Уровень

```js
{
  id: '3-2', chapter: 3, title: 'Длинный ход',
  story: 'Реплика Аи перед уровнем',          // 1–2 предложения
  task: 'Засади все грядки вдоль стены и вернись к росоуловителю',
  commands: ['up','down','left','right','plant','repeat','while'],
  conditions: ['free_right','free_down','wall_right','wall_down'],
  variants: [ '…ASCII…', '…ASCII…', '…ASCII…' ],  // 1–4 поля
  finishRequired: true,
  optimalBlocks: 4,
  water: null,                                 // глава 4: число порций воды
  solution: 'нц пока справа свободно\n  вправо\n  посадить\nкц',   // эталон в КуМире
  wrongSolutions: [ 'вправо\nпосадить\n…' ]    // подгонки, которые ОБЯЗАНЫ провалиться
}
```

### Программа (дерево)

```js
{ main: [ /* блоки */ ], procs: { 'засадить ряд': [ /* блоки */ ] } }

{ t: 'cmd', name: 'right' }                       // up down left right plant water weed
{ t: 'repeat', n: 5, body: [] }
{ t: 'while', cond: { name: 'free_right', not: false }, body: [] }
{ t: 'if', cond: { name: 'is_dry', not: false }, then: [], else: [] }
{ t: 'call', name: 'засадить ряд' }
```

Каждый блок получает `id` для подсветки при выполнении и сообщений об ошибках.

### Результат выполнения

Интерпретатор — генератор, который на каждом шаге отдаёт `{ blockId, state }`.
Завершение: `{ ok: true }` или `{ ok: false, error: 'wall' | 'outside' | 'quicksand' |
'plant_rock' | 'plant_salt' | 'no_water' | 'step_limit' | 'recursion', blockId, step }`.
Лимит шагов — 1000, глубина вызовов — 50.

## 4. Названия команд и условий

| Ключ | В блоке и в КуМире |
|---|---|
| up / down / left / right | вверх / вниз / влево / вправо |
| plant | посадить (в справке: «в КуМире — закрасить») |
| water / weed | полить / выполоть (только в игре) |
| free_right … / wall_right … | справа свободно … / справа стена … |
| is_dry / has_weed / is_planted | клетка сухая / на клетке сорняк / клетка засажена |
| repeat | нц N раз … кц |
| while | нц пока <условие> … кц |
| if | если <условие> то … иначе … все |
| proc / call | алг имя нач … кон / имя |

## 5. Этапы

Каждый этап заканчивается: всё собирается (`npm run game:klever`), тесты проходят
(`npm test`), сделан коммит. В конце сессии — короткий отчёт: что сделано, что проверить руками.

### Этап 0. Внешний вид
- Клевер в SVG (покой, поворот, посадка, авария), клетка песка, переборка, грядка, росток,
  камень, сухая почва, сорняк, солончак, зыбучий песок, росоуловитель.
- Статичный макет экрана: поле слева, программа справа, панель «Пуск / Шаг / Стоп / скорость» снизу.
- Каркас сборки `scripts/build-game.mjs` и `template.html`.
- **Готово, когда:** автор утвердил вид. Логики ещё нет.

### Этап 1. Ядро
- `world.js`: разбор и печать ASCII-карты, движение, стены, посадка.
- `program.js`, `interpreter.js` — только команды движения и `plant`.
- `render.js`: поле, движение Клевера с анимацией, подсветка текущего блока.
- `editor.js`: добавление команд кликом, удаление, перестановка (кнопки ↑↓), курсор вставки.
- Пуск, шаг, стоп, сброс, скорость. Сообщения об авариях со ссылкой на блок.
- Глава 1 — 5 уровней.
- **Тесты:** разбор/печать карты туда-обратно; каждая авария; эталоны главы 1 проходят.

### Этап 2. Циклы и проверка на вариантах
- `repeat`, `while`, условия про стены, вложенность блоков (блок-«папка»).
- `checker.js`: прогон на всех вариантах, отчёт «Поле 2 из 3: врезался в стену на 9-м шаге»,
  открытие проваленного варианта для пошагового просмотра; разница с целью на поле
  (недосаженное пунктиром, лишнее красным).
- Лимит шагов с понятным сообщением про бесконечный цикл.
- Главы 2 и 3 — по 5 уровней.
- **Тесты:** эталоны проходят на всех вариантах; **каждое** `wrongSolutions` проваливается
  хотя бы на одном варианте; бесконечный цикл останавливается лимитом.

### Этап 3. Ветвление и вспомогательные алгоритмы
- `if … else`, условия про клетку, команды `water` и `weed`, бак воды с лимитом.
- Свои алгоритмы: создать, назвать, вызвать; защита от бесконечной рекурсии.
- Главы 4 и 5 — по 5 уровней.
- **Тесты:** то же для новых глав; нехватка воды; рекурсия.
- После этого этапа игру уже можно давать на уроке.

### Этап 4. КуМир
- `kumir.js`: дерево → текст (вкладка «Текст» рядом с блоками, только чтение).
- Затем текст → дерево: разбор с сообщениями по-русски и номером строки
  («Строка 4: после „нц“ ожидалось „пока“ или число»).
- Глава 6 — задачи в формате ОГЭ, решаются текстом.
- **Тесты:** для всех эталонов текст → дерево → текст даёт тот же текст;
  10+ типичных синтаксических ошибок дают понятные сообщения.

### Этап 5. Прогресс, звёзды, контрольная
- Звёзды: ⭐ решено, ⭐⭐ с первого запуска, ⭐⭐⭐ блоков не больше `optimalBlocks`.
- Карта станции с главами; отсеки зеленеют; прогресс в `storage.js`.
- `exam.js`: контрольная по стандарту из AGENTS.md — 10 минут по `Date.now()`, фамилия,
  объект `EXAM` с настройками, 5–6 задач глав 2–4, баллы за задачу и звёзды, оценка,
  учёт уходов со страницы, «Над чем поработать» по типам ошибок.
- **Тесты:** сценарий контрольной с переводом времени.

### Этап 6. Редактор уровней для учителя
- Рисование поля кликами: стены, объекты, старт, финиш, несколько вариантов.
- Задание, набор доступных команд, оптимум.
- Ссылка `?level=<base64url(JSON)>` и QR; открытие уровня из ссылки.
- **Тесты:** уровень → ссылка → уровень без потерь.

### Этап 7. Полировка и публикация
- Справка, сценки глав, звук (Web Audio, с кнопкой выключения), финальная сцена с дождём.
- Работа на доске без клавиатуры, крупные элементы, `prefers-reduced-motion`.
- Карточка `src/content/items/klever.md`, сборка сайта, чек-лист из AGENTS.md.

## 6. Тесты: как писать

- Только `node:test` и `node:assert`, без фреймворков.
- Логические модули импортируются напрямую, DOM не нужен.
- Обязательный общий тест `levels.test.mjs`: для **каждого** уровня кампании
  эталон проходит на всех вариантах, все `wrongSolutions` проваливаются,
  в каждом варианте старт один и цели достижимы.
- Падающий тест нельзя «чинить» правкой ожиданий — сначала разберись, что сломалось.

## 7. Правила для этой игры

- Тексты и названия — только по `WORLD.md`; ничего из «Дюны» и других произведений.
- Клевер никогда не «думает сам»: любое его действие — следствие программы ученика.
- Сообщение об ошибке всегда отвечает на три вопроса: что случилось, на каком шаге и в каком
  блоке, что попробовать.
- Блочный редактор управляется кликами; перетаскивание — только дополнительно.
- Уровни кампании хранятся в `levels.js` в ASCII — их должен уметь править человек.
- Не меняй формат уровня и дерева программы без обновления этого файла.
