Побеждает тот, кто не сделал последний ход

Разберём игру с камнями: от русского текста до рекурсивной функции. Каждую строчку кода можно выбрать, каждый ход — проверить самому.

Условие учебной игры

В куче лежит S камней, S > 35. Игроки ходят по очереди; первым ходит Петя.

За ход можно убрать 9 камней или уменьшить количество камней вдвое. При нечётном количестве округляем вниз: например, из 25 камней остаётся 12.

Игра заканчивается, когда в куче становится меньше 23 камней. Игрок, сделавший такой ход, проигрывает.

Стратегия называется выигрышной, если она обеспечивает победу при любом выборе соперника.

Числа в примерах составлены для этого урока. Оба возможных хода надо учитывать.

Почему именно // 2?

Если количество камней нечётное, на две равные целые части его не разделить.

25 / 2 = 12.5 — дробь, а 25 // 2 = 12 — количество камней, которое останется.

Условие конца: меньше 23, то есть x < 23. Если осталось ровно 23, игра продолжается.

Почему иногда выгодно оставить камни сопернику?

Здесь проигрывает тот, кто своим ходом получил меньше 23. Значит, наша цель — поставить соперника в безвыходное положение.

Выигрышная и проигрышная позиция

23–31 камень — ловушка.При любом ходе останется меньше 23, поэтому тот, кому сейчас ходить, проиграет.
40 камней — есть хороший ход.40 → 31 (убрать 9). Следующий игрок вынужден проиграть. Но 40 → 20 — немедленный проигрыш ходящего.

Выигрышная стратегия не предполагает, что соперник ошибётся. Она должна работать при каждом его возможном ответе.

Если выбирает наш игрок — хватит одного подходящего хода. Если выбирает соперник — должны подходить все его ходы.
3

Что считает переменная m?

m — число оставшихся общих ходов, а не ходов только Пети или только Вани.

Выбери длину партии:

Почему m == 0?

В нашем варианте рекурсии требуется, чтобы игра закончилась именно на проверяемом ходе.

В момент окончанияm == 0m % 2 == 0
m = 0 — ровно вовремяTrueTrue
m = 2 — на два хода раньшеFalseTrue

Если использовать только чётность, преждевременное окончание при m = 2 тоже будет засчитано. Поэтому для проверки точного момента окончания используем m == 0.

Почему это не общее правило всех игр?

Мы намеренно строим функцию для строго заданного номера последнего хода.

В другой задаче могут спрашивать о выигрыше не позднее определённого хода. Тогда смысл базы рекурсии будет другим, и проверку нужно выбирать по смыслу формулировки.

Две остановки рекурсииif x < 23: return m == 0if m == 0: return False

Сначала проверяем окончание игры, а затем исчерпание отведённых ходов. Если поменять порядок, победа на последнем ходе потеряется.

Почему при нечётном m здесь all()?

m нечётное → all(h)Ход сейчас выбирает игрок, который должен проиграть на последнем ходе. Мы обязаны учесть все его ответы.
m чётное → any(h)Ход выбирает будущий победитель. Ему достаточно одного подходящего варианта.

Здесь записано any(h) if (m - 1) % 2 != 0 else all(h). Равнозначная запись: all(h) if m % 2 != 0 else any(h).

Почему условия для вопросов содержат not?
not исключает более ранние гарантированные победы, о которых прямо сказано в формулировке. Но при строго заданной длине партии нужно отдельно помнить: раннее окончание в самой функции уже даёт False. Поэтому разные модели («ровно» и «не позднее») не следует смешивать.
Итоговое правило: перед написанием функции выясни, кто проигрывает при завершении игры, какой именно ход проверяем, и кто выбирает следующий ход. Уже после этого подбираются базовые случаи, any, all и значения m.
