# Устройство сайта

Спецификация для разработки. Что уже есть, что строим на этапе 2 и что закладываем под будущую подписку.

## Сейчас (этап 1)

- Astro 7, статическая сборка, GitHub Pages.
- Коллекция `items` (`src/content/items/*.md`) — все продукты: игры, тренажёры, курсы, программы.
- Страницы: главная (разделы по классам), каталог (фильтры `type`, `grade`, поиск `q` в адресе),
  страница материала `/item/<slug>/` с описанием и QR-кодом.
- Игры — самодостаточные HTML в `public/games/`.

## Адреса — правило на всё время жизни сайта

Всё, что уходит наружу (посты ВК, QR-коды, печать, письма), указывает на **страницы**, а не на файлы:

| Адрес | Что это |
|---|---|
| `/` | стена с роликами |
| `/catalog/?grade=8` | каталог с фильтрами |
| `/item/<slug>/` | страница материала: описание, ролик, кнопка «Играть», QR |
| `/igra/<slug>/` | запуск игры (сейчас — страница-обёртка, открывающая `games/<slug>.html`) |

Почему: когда появится подписка, `/igra/<slug>/` сможет проверить доступ, а файл переедет за авторизацию —
и ни одна ссылка не сломается. Slug после публикации **не меняется никогда**.

## Стена (этап 2)

Главная страница — лента постов, как стена в ВК: короткие ролики с процессом игры привлекают лучше описаний.

**Коллекция `posts`** (`src/content/posts/*.md`):

```markdown
---
date: 2026-10-15
item: poiskovye-krugi          # slug материала из items (необязательно — пост может быть новостью)
video: posts/poiskovye-krugi.mp4
poster: posts/poiskovye-krugi.jpg
title: "Поисковые круги: закрась запрос"
pinned: false
---
Короткий текст поста, 1–3 абзаца.
```

**Карточка поста:**
- ролик `<video muted loop playsinline preload="metadata" poster=…>`; проигрывается, когда карточка видна
  (IntersectionObserver), и останавливается, когда ушла с экрана; одновременно играет не больше 1–2 роликов;
- при `prefers-reduced-motion` и экономии трафика (`navigator.connection.saveData`) — только постер и кнопка ▶;
- заголовок, класс и тема (из связанного материала), дата;
- кнопки «Играть» (→ `/igra/<slug>/`) и «Подробнее» (→ `/item/<slug>/`); значок доступа, если не бесплатно.

**Лента:** новые сверху, закреплённые первыми; фильтр по классу как в каталоге; подгрузка порциями по 10.

**Ролики:**
- храним на сайте (`public/posts/`), а не встраиваем плеер ВК: в школах ВК часто заблокирован;
- формат: mp4 H.264, без звука, 720p, 15–30 с, 2–4 МБ, постер — первый выразительный кадр;
- скрипт `scripts/prepare-video.mjs` на ffmpeg: исходник → сжатый mp4 + постер jpg;
- когда роликов станет много (сотни МБ) — вынести в объектное хранилище в РФ; адреса роликов
  в карточках задавать так, чтобы базовый адрес хранилища менялся в одном месте.

## Модель доступа (закладываем сейчас, включаем на этапе 4)

**У продукта** — поле `access` в карточке: `free` | `paid` | `external` | `soon`. Сейчас у всех `free`.
Позже возможно поле `plans: [base, pro]` — к каким тарифам относится продукт.

**Внутри игры** — режимы с уровнем доступа. Конфиг в начале скрипта игры:

```js
const ACCESS = { train: 'free', exam: 'free' };   // позже: exam: 'paid'
```

Игра узнаёт о доступе пользователя через `window.SITE_ACCESS` (выставляет страница-обёртка `/igra/<slug>/`)
или считает всё доступным, если игру открыли отдельно. Закрытый режим показывает объяснение
и кнопку «Подписаться», а не исчезает молча.

**Проверка доступа (этап 4а):** вход через VK ID → серверная проверка подписки VK Donut → короткоживущий
токен → `/igra/<slug>/` отдаёт игру с `SITE_ACCESS`. Для этого нужен сервер (не GitHub Pages):
выбор хостинга согласуется с автором (152-ФЗ — серверы в РФ).

## Чего не делаем без автора

Сервер, база данных, вход, платежи, аналитика, сторонние скрипты, смена хостинга или домена,
удаление страниц и смена slug. Подробно — `AGENTS.md`, раздел 9.
